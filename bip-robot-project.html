How it's built

Mechanical. Every structural part is designed in Fusion 360 and 3D printed. Each leg has five joints (hip yaw, hip, knee, ankle pitch, ankle roll) on MG996R servos. Hip yaw is limited in firmware so the toes can't collide when the feet turn in.

Walking. The main ESP32-S3 drives the leg servos through a PCA9685 and runs the inverse kinematics and gait at 50 Hz, with an MPU-6050 for balance and heading hold. Every servo is calibrated (zero, direction, limits) and the values are saved on the board. Servos start limp and every move is ramped, because these hobby servos have no position feedback and jumping to a stored angle can break a joint.

Simulation. I built a MuJoCo digital twin that runs the same C++ gait code as the robot. The gait on the ESP32 matches the simulator to within 0.0005°. I use it to test gait settings and balance gains before trying them on the real robot. The latest real tests showed the twin is still wrong in pitch, so a gait that works in the sim doesn't work on Bip yet.

Face and senses. An ESP32-C3 draws the face: two GC9A01 round displays for the eyes and an SSD1306 OLED mouth, all procedurally animated. A XIAO ESP32-S3 Sense provides the camera and microphones, a MAX98357A amp drives the speaker, and an HC-SR04 sonar sits in the chest. Speech recognition and the conversation run on my laptop, using Claude as the brain.

What I've learned so far
The hard part is the gap between the sim and the real robot
In the simulator Bip walks with a lot less sway, but on the real table the same settings fall within a few steps. Most falls happen when it starts or stops walking. The next steps are to measure the real servo lag and its real weight and balance point so the twin matches, add bigger feet, and give the servos a proper 6 V supply.
